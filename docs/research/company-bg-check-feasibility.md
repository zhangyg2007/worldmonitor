# WorldMonitor 改造为「本地公司背景调查」产品的可行性调研报告

> 调研日期：2026-09-24 ｜ 方法：多轮深度联网检索（企查查/天眼查开放平台定价页、最高法案例库、央视/新华网调查报道、律所专业文章、GitHub 生态）
> 背景：WorldMonitor 为开源地缘情报仪表盘（docker compose 部署在腾讯云），拟评估改造为本地【公司背景调查】产品的可行性。

---

## 结论速览

1. **可行性：中高（企业侧），低（自然人侧）。** WorldMonitor 已有的"多源采集 → 图/向量存储 → 仪表盘聚合 → 报告输出"骨架与公司背调产品架构高度同构，改造成本主要在数据层（接商业数据 API + 合法自建管道），而非应用层。
2. **合规是生死线，不是附加项。** 企业工商/司法/处罚数据本身属公开信息，通过合规数据源（开放平台 API、公开渠道授权抓取）处理风险可控；但一旦背调报告触及自然人敏感信息（婚姻、征信、未公开诉讼、健康），就进入 PIPL 高敏感区，已有背调公司被法院判定侵权判例 [25][26]。央视 2026-09 调查证实行业存在"31 元起查犯罪/诉讼/网贷记录"的灰产 [26]——产品定位必须与灰产划清界限。
3. **技术栈复用度高：** 现有 docker compose + 采集调度 + 图库（如 neo4j）正好对口"股权穿透/关联关系图谱"这一背调核心卖点；股权知识图谱用 neo4j 有成熟方案 [18]。
4. **建议形态：** 做"**企业尽调报告生成器**"（股东/高管/涉诉/处罚/股权穿透 + 目标国风险），数据全部走商业开放平台 API（企查查/天眼查/启信宝）或公开渠道，**不做自然人深度背调**，把 WorldMonitor 的地缘安全数据作为差异化"海外主体+目标国制裁/安全风险"模块。

- **启信宝**：股权穿透 12 层（行业最深）、按次 0.015 元/次起（最低档）、8 类 API、调用限制低，适合批量集成进 CRM/ERP；短板是更新 T+2、司法只覆盖重点省市。[2]

- **合合信息（TextIn）**：强项是智能文档处理/OCR（报告解析、证照识别），可作为"用户上传尽调底稿→自动抽取结构化字段"的辅助层，而非主体数据源。[4]

## 2. 合规红线（最重要章节）

### 2.1 PIPL 对"公司背调"的边界：企业 vs 自然人

- 背调通常涉及三类数据：**企业主体信息**（工商、涉诉、行政处罚——公开信息，合规处理无障碍）；**企业关联自然人信息**（法定代表人、高管任职——公开登记信息，可查）；**自然人深度信息**（婚姻、健康、征信、犯罪记录、未公开诉讼——敏感个人信息）。
- 《个人信息保护法》处理敏感个人信息须"特定目的+充分必要+单独同意+严格保护"。员工背调必须取得本人有效授权授权；"员工不知情下展开调查是侵犯个人信息权益的典型违法" [8]。
- 《劳动合同法》第 8 条只赋予用人单位了解"与劳动合同直接相关的基本情况"的权利，且"哪些直接相关"没有法定清单——这正是一些背调公司把婚姻、普通民事纠纷塞进报告的灰色空间，多位学者呼吁立法出正负面清单 [26]。
- 关键判例（直接适用于背调行业）：**北京某背调公司未核实习访人所述"生活作风/价值观问题"即标注"黄灯"写入报告，被判侵犯名誉权，赔偿精神损害金**（丰台法院判决、二审维持）[25]。法官明确指出背调公司对"易损害被调查人名誉的内容应负有更高的合理核实注意义务" [25]。

**产品设计含义：**
1. 报告字段做**白名单制**——只出现企业主体+公开登记的高管任职，不出现自然人深度字段（婚姻/健康/征信/普通民事诉讼）；
2. 每一条结论必须能回答"数据来源是否合法、是否核实过"（对应 [25] 的核实义务）；
3. 若客户坚持要自然人字段，产品应提示其法律风险而非代查——这是与灰产背调（31 元起查犯罪/网贷记录 [26]）的法律分界线。

### 2.2 爬虫/数据获取刑事红线（2023–2025 真实判例）

| 案例 | 事实 | 判决 | 来源 |
|---|---|---|---|
| 上海静安（2025-06 一审）Y 公司 | 爬虫非法下载某科技企业 1800 余万条专业数据 | 非法获取计算机信息系统数据罪：单位罚金 5 万；负责人**有期徒刑 3 年（缓 3 年）+ 罚金 3 万** | [9] |
| 上海普陀（2025-09 提起公诉）陈某等 3 人 | 爬取 8 亿余条餐饮商超及地图数据生成商业报告牟利 | 涉案 5 万余元，公诉中 | [9] |
| 上海普陀（2024）王某案 | 开发破解"得物"App 防护的爬虫售卖，两年获利 60 余万 | 提供侵入计算机信息系统程序罪：**有期 3 年缓 3 年 + 罚金 8 万** | [9] |
| 最高法入库案例（2024）丁某案 | 明知"汇易获客"软件专门用于侵入短视频平台服务器获取受限数据仍转卖 | 提供侵入、非法控制计算机信息系统程序、工具罪 | [10] |
| 最高法典型案例 | 倒卖学籍学历信息、"社工库"1.7 亿条数据出售、铁路"内鬼"贩卖行程等 | 侵犯公民个人信息罪 3 年 8 个月–7 年不等 | [11] |

**司法认定核心**："侵入"= 违背他人意愿、未经许可进入系统或**超越授权边界**——"用合法账号登录但用技术手段把导出权限提升到全库底层数据"同样构罪 [9]。这直接判了"拿一个企查查账号抓全库数据做产品"的死刑。

### 2.3 数据来源合法性风险矩阵（本产品视角）

| 数据获取方式 | 风险等级 | 说明 |
|---|---|---|
| 商业开放平台 API（按次付费、实名+场景审核） | **低** | 数据商承担源头合规，你方是合法下游；注意合同转售条款 |
| 官方公开平台单点核验（gsxt/执行信息网，低频） | **低-中** | 用于核实客户提交的信息，规模化批量抓取则升档 |
| 无 API 平台的批量自动化抓取（裁判文书网等） | **高-极高** | 验证码=反爬措施，绕过即可能触犯 §285[9][10] |
| 购买灰产数据包/"社工库"接口 | **极高** | 侵犯公民个人信息罪共犯风险 [8][11]，且数据不可审计 |

## 3. 产品对标

### 3.1 商业对标（要超越/区隔的对象）

- **企查查「第三方风险排查系统」**（已接入 DeepSeek）：AI 解读分析（经营稳定性/信用履约/偿债能力）、图计算股权穿透+任职网络+共同投标围标分析。某汽车集团年均排查 5000+ 供应商、合规审查通过率 72%→99.3% ；某电子集团 3500+ 经销商全周期风控。[12]
- **天眼查 C 端报告 + 开放平台 API**：功能最全的"查公司"心智。[3]
- **灰产背调**（央视 2026-09 调查）：31 元/人 基础套餐（身份/学历/诉讼/失信）到 600 元+/人 顶配（3 段履历+法院诉讼查询+工作访谈）；单项 10–260 元；甚至卖"改记录/冒充前公司人事"服务 [26]。**这正是监管将要打击的对象，也是本产品必须反着做的清单。**

### 3.2 需求方对标（我们的买家）

- **银行对公信贷尽调**：监管要求尽职免责制度化、受益所有人信息管理制度化（2024 银行业监管主线）[13]。尽调报告标准模块 = 工商基础/股权结构/关联关系/涉诉被执行/行政处罚/行业风险/担保圈——本产品 §6 的报告结构应直接对齐这套字段。
- **企业供应商准入/招投标风控**：企查查案例证明这是付费最痛的场景 [12]。
- **出海/跨境业务**：国内主体信用 + 高管背景 + 目标国制裁（OFAC SDN 等国际名单）风险，是本产品相对纯国内竞品（企查查/天眼查）的**差异化空白**。

## 4. 技术参考：开源生态与股权知识图谱

### 4.1 GitHub 现状

- **数据爬取类**：`bouxin/company-crawler`（企查查/天眼查小程序抓包）、`yxlspider/webinfo-crawler`（关键字爬公司）、`yez77/tianyancha`（"跑 main_all.py 爬 90% 天眼查公司"）[7]——**定位全部是个人/灰产工具，无商用许可、无维护**，不可作为产品基座。
- **知识图谱类**：`pranavsaji/enterprise-kg`——企业图谱平台骨架（Connectors→Kafka→Spark 对齐→Neo4j(SHACL+provenance)→FastAPI+OPA 权限+NL2Cypher）[14]；百度社区《Neo4j 构建工商企业图谱》给出完整方案：统一信用代码做主键、`MATCH (c:Company)-[:SHAREHOLDER*1..5]->(p:Person)` 递归穿透、APOC 增量同步、Kafka+Streams 实时、ABAC 权限。[18]
- **结论**：开源圈没有"公司背调产品"级开源项目，只有零件。WorldMonitor 的采集调度+存储+仪表盘反而是现成资产，**自建应用层是正确路径**。

### 4.2 股权知识图谱设计（neo4j）

```
(:Company {creditCode(主键), name, regCapital, industry, country, ...})
(:Person  {id, name, position, ...})           # 仅公开登记信息
(:Event   {type: 司法|处罚|变更|舆情, ts, source, url})

(:Company)-[:HOLDS {ratio}]->(:Company)        # 股权穿透，支持 1..N 递归
(:Person)-[:IS_OFFICER_OF {role}]->(:Company)
(:Company)-[:INVOLVED_IN {role: 原告|被告|被执行人}]->(:Event)
(:Company)-[:ASSURED_BY]->(:Company)           # 担保圈
(:Company)-[:OPERATES_IN {riskLevel}]->(:Region)  # 目标国/地区风险（WorldMonitor 融合点）
```

查询范式（控制人识别，含离岸层）[18]：
```cypher
MATCH (c:Company)-[:HOLDS*1..5]->(p:Person)
WHERE c.name = $target AND p.country IN $offshore
RETURN p, COUNT(DISTINCT c) AS c
```
建议架构：API 适配器 → Kafka/队列 → 清洗(统一信用代码对齐"一企多码") → postgres(明细)+neo4j(关系)+可选向量库(舆情/报告语义) → 报告生成服务（LLM 结构化输出，对齐企查查"AI 解读"形态 [12]）→ WorldMonitor 仪表盘展示。

## 5. 与地缘安全数据融合（WorldMonitor 的独特价值）

WorldMonitor 是地缘情报仪表盘——对"公司背调"的改造价值在于把**第三块数据（目标国/地区风险与安全局势）**接进尽调报告，这是企查查/天眼查都没有的：

**融合尽调报告结构设计**（六层）：

1. **主体层**：工商照面、全球主体对应（出海子公司链）
2. **结构层**：股权穿透（N 层）、实控人、担保圈、关联族群
3. **司法层**：涉诉/被执行/失信/行政处罚（仅主体，白名单字段）
4. **经营层**：经营异常、税务、资质、行业风险、舆情
5. **地缘层（WorldMonitor 原生）**：
   - 目标国风险评级（政治稳定/制裁风险/出口管制，如 OFAC SDN/CMIC 名单交叉核验 [15]）
   - 高管/关联主体的制裁名单命中
   - 供应链中断/冲突事件时间线
   - 目标国法律/数据跨境合规要点
6. **结论层**：LLM 生成的风险摘要+证据链（每条结论挂来源 URL，满足 [25] 的核实义务与审计要求）

该六层结构与银行对公尽调字段天然对齐 [13]，而第 5 层正是对标竞品的差异化。

## 6. 落地路线建议

| 阶段 | 内容 | 周期建议 |
|---|---|---|
| P0 验证 | 接 1 家开放平台 API（建议先启信宝低价档 0.015 元/次起 [2]）跑通"企业风险扫描"单企业报告；neo4j 导入股东/任职图 | 2–3 周 |
| P1 产品 | 六层报告生成 + WorldMonitor 地缘层接入（制裁名单 API + 现有世界数据）；白名单字段+来源溯源 UI | 4–6 周 |
| P2 规模 | 双源校验、批量名单监控（企查查 1000 次套餐/天眼查按次 [1][3]）、经销商/供应商全周期风控场景（对标 [12]） | 持续 |

**合规 Checklist（写进产品代码评审）**：
- [ ] 所有数据接口调用方实名、场景备案（[1] 要求）
- [ ] 报告字段白名单，禁止自然人敏感字段（婚姻/征信/健康/未公开诉讼）
- [ ] 禁止无 API 平台的批量自动化抓取（§2.2 判例红线）
- [ ] 每条结论可溯源（来源 URL + 时间戳 + 核实状态）[25]
- [ ] 不采购、不使用"社工库"/灰产数据 [11][26]

**成本粗算（单份报告，企业侧）**：数据接口 6–40 元（风险扫描 6 元 [1] + 穿透/关系若干次 0.015–0.15 元/次 [2][3]）+ LLM 推理 ~1 元 + 基础设施摊销 < 0.5 元。灰产同规格市场价 ≥31 元/人 [26]，正规企业报告可定价 100–500 元/份仍有毛利与合规溢价。
